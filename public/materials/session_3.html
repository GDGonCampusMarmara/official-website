01

Why this workshop exists

The first design is easy to explain but gets messy fast. The second design is clean but too heavy for a single teaching session. This workshop keeps the good parts of both.

Workshop 1

Fast, simple, beginner-friendly

  • class-based AIAgent
  • two agents debating in a loop
  • easy to live-code
  • hardcoded and stateful
Workshop 2

Architecturally cleaner

  • stateless functional core
  • plugin shell
  • agents as plain data
  • too much boilerplate for 45 minutes
Workshop 3

The middle path

  • simple enough to teach live
  • clean enough to grow later
  • small project, real architecture
  • no framework gravity

The point is not to make agents look clever. The point is to make the system understandable when something breaks at 2 a.m.

02

What we are building

A small Node.js app where Ada the optimist debates Byron the skeptic. Byron can request browser research exactly once, or be forced to use it for a deterministic demo. Ollama streams replies. Lightpanda provides one read-only browser tool. Final state prints as JSON.

04

Key design rules

Keep the core boring. Put opinions in system definitions. Put side effects in plugins. Pass state explicitly.

Rule 1

Agents are plain data

No instances hiding history. An agent is just a config object with persona, model, and allowed tools.

Rule 2

State is explicit

The whole workshop rests on passing state through functions instead of burying it inside objects.

Rule 3

Runtime has no debate knowledge

It executes steps from a plan. It does not know Ada, Byron, or what a skeptic is.

Rule 4

Tools are requested, then approved

The model can ask. Policy decides. The runtime does not trust the model by default.

Rule 5

Side effects live in plugins

LLM calls, browser automation, and console rendering are ports, not core logic.

Rule 6

Streaming is UX, accumulated content is state

We stream tokens live for the audience, but we still collect final content and store it explicitly.

System definition concept

The system defines agents, initial state, plan, task builders, rounds, and reusable skills. The runtime executes this without knowing it is a debate.

File: src/systems/personaDebate.js
import { loadSkill } from "../core/loadSkill.js";

const practicalCaseBuilder = loadSkill("practical-case-builder");
const evidenceStressTester = loadSkill("evidence-stress-tester");

export const personaDebateSystem = {
  id: "persona-debate",
  version: "3.1.0",

  settings: {
    rounds: Number.parseInt(process.env.ROUNDS ?? "2", 10),
  },

  agents: {
    optimist: {
      id: "optimist",
      name: "Ada",
      model: process.env.OLLAMA_MODEL ?? "qwen2.5-coder:7b",
      allowedTools: [],
      skills: [practicalCaseBuilder],
      persona: `You are Ada, a technology optimist.
Keep your answer under 160 words.
Be concrete.
End with one question for Byron.`,
    },

    skeptic: {
      id: "skeptic",
      name: "Byron",
      model: process.env.OLLAMA_MODEL ?? "qwen2.5-coder:7b",
      allowedTools: ["browser.search"],
      skills: [evidenceStressTester],
      persona: `You are Byron, an ethical skeptic.
Keep your answer under 180 words.
You may request browser research exactly once by writing:
[[tool:browser.search {"query":"your search query"}]]
After tool results arrive, do not request another tool.`,
    },
  },

  initialState({ input }) {
    return {
      topic: input.topic,
      statement: input.statement ?? "",
      searchQuery: input.searchQuery ?? "",
      requireSearch: Boolean(input.requireSearch),
      round: 1,
      transcript: [],
      toolResults: [],
    };
  },

  plan({ system }) {
    const steps = [];
    for (let round = 1; round <= system.settings.rounds; round += 1) {
      steps.push({ id: `round-${round}-optimist`, kind: "agent", round, agentId: "optimist", task({ state }) {
        return state.transcript.length === 0
          ? "Open the debate with your strongest practical argument."
          : "Respond to Byron's latest point and strengthen your position.";
      }});
      steps.push({ id: `round-${round}-skeptic`, kind: "agent", round, agentId: "skeptic", task() {
        return round === 1
          ? "Respond to Ada. You may use your browser.search tool if research helps."
          : "Respond to Ada's latest argument. You may use your browser.search tool if research helps.";
      }});
    }
    return steps;
  },
};
07

Generic runtime concept

Runtime should not know Ada, Byron, debate, browser search, or console rendering. It only executes steps from a plan, passes state forward, and lets plugins do the side effects.

File: src/core/runSystem.js
import { runStep } from "./runStep.js";

export async function runSystem({ system, input, ports }) {
  let state = system.initialState({ input, system, ports });
  const steps = system.plan({ state, system, ports });

  for (const step of steps) {
    state = {
      ...state,
      round: step.round ?? state.round,
    };

    ports.renderer?.stepStarted?.({ step, state });

    state = await runStep({
      step,
      system,
      state,
      ports,
    });

    ports.renderer?.stepCompleted?.({ step, state });
  }

  return state;
}
File: src/core/runStep.js
import { buildMessages } from "./buildMessages.js";
import { applyToolRequests } from "./applyToolRequests.js";

const BROWSER_SEARCH_PATTERN = /\[\[tool:browser\.search\s+.+?\]\]/g;

function hasBrowserSearchResult(state) {
  return state.toolResults.some((result) => result.toolId === "browser.search");
}

function removeBrowserSearchRequests(content) {
  return content.replace(BROWSER_SEARCH_PATTERN, "").trim();
}

async function runBrowserSearch({ query, agent, state, ports }) {
  const toolId = "browser.search";
  const input = { query };
  const tool = ports.tools[toolId];

  ports.renderer?.toolStarted?.({ toolId, input });
  const output = await tool.invoke(input);
  ports.renderer?.toolCompleted?.({ toolId, output });

  return {
    ...state,
    toolResults: [
      ...state.toolResults,
      { agentId: agent.id, toolId, input, output },
    ],
  };
}

export async function runStep({ step, system, state, ports }) {
  const agent = system.agents[step.agentId];
  const task = typeof step.task === "function"
    ? step.task({ step, state, system, ports, agent })
    : step.task;
  const alreadySearched = hasBrowserSearchResult(state);
  const effectiveTask = agent.id === "skeptic" && state.requireSearch && alreadySearched
    ? `${task} Browser search has already been used; do not request more tools.`
    : task;

  const messages = buildMessages({ agent, state, task: effectiveTask });
  ports.renderer?.agentStarted?.({ agent, step });

  const first = await ports.llm.streamChat({
    model: agent.model,
    messages,
    onToken: (token) => ports.renderer?.token?.(token),
  });

  const contentForToolRequests = agent.id === "skeptic" && state.requireSearch && alreadySearched
    ? removeBrowserSearchRequests(first.content)
    : first.content;

  const { state: stateAfterTools, usedTools } = await applyToolRequests({
    content: contentForToolRequests,
    agent,
    state,
    ports,
  });

  let finalContent = contentForToolRequests;
  let nextState = stateAfterTools;
  const shouldForceSearch = agent.id === "skeptic"
    && state.requireSearch
    && !alreadySearched
    && !hasBrowserSearchResult(stateAfterTools);

  if (shouldForceSearch) {
    nextState = await runBrowserSearch({
      query: state.searchQuery || state.topic,
      agent,
      state: nextState,
      ports,
    });
  }

  if (usedTools || shouldForceSearch) {
    const followUpMessages = buildMessages({
      agent,
      state: nextState,
      task: "Use the available tool results. Do not request more tools.",
    });
    ports.renderer?.agentStarted?.({ agent, step, followUp: true });
    const second = await ports.llm.streamChat({
      model: agent.model,
      messages: followUpMessages,
      onToken: (token) => ports.renderer?.token?.(token),
    });
    finalContent = second.content;
  }

  return {
    ...nextState,
    transcript: [
      ...nextState.transcript,
      {
        round: step.round ?? nextState.round,
        agentId: agent.id,
        speaker: agent.name,
        content: finalContent.trim(),
      },
    ],
  };
}
08

Messages, tools, policy, and skills

Prompt construction is pure. Tool requests are parsed. Policy decides. Tool results go back into state. Skills are loaded as plain text and attached to agents without changing the runtime.

File: src/core/buildMessages.js
export function formatTranscript(transcript = []) {
  return transcript
    .map((entry) => `${entry.speaker}: ${entry.content}`)
    .join("\n\n");
}

export function formatToolResults(toolResults = []) {
  return toolResults
    .map((result) => {
      return `[${result.toolId}] ${result.input.query}
TITLE: ${result.output.title}
URL: ${result.output.url}
EXTRACT:
${result.output.extract}`;
    })
    .join("\n\n");
}

export function formatSkills(skills = []) {
  return skills
    .map((skill) => {
      return `${skill.name}
Description: ${skill.description}
Location: ${skill.location}

${skill.body}`;
    })
    .join("\n\n");
}

export function buildMessages({ agent, state, task }) {
  const transcript = formatTranscript(state.transcript);
  const tools = formatToolResults(state.toolResults);
  const skills = formatSkills(agent.skills);

  return [
    {
      role: "system",
      content: [agent.persona, skills ? `Skills:
${skills}` : ""].filter(Boolean).join("\n\n"),
    },
    {
      role: "user",
      content: [
        `Topic: ${state.topic}`,
        state.statement ? `Statement: ${state.statement}` : "",
        transcript ? `Transcript:
${transcript}` : "",
        tools ? `Tool Results:
${tools}` : "",
        `Task: ${task}`,
      ].filter(Boolean).join("\n\n"),
    },
  ];
}
File: src/core/applyToolRequests.js
const TOOL_PATTERN = /\[\[tool:([a-zA-Z0-9._-]+)\s+(.+?)\]\]/g;

export async function applyToolRequests({ content, agent, state, ports }) {
  const matches = [...content.matchAll(TOOL_PATTERN)];
  if (!matches.length) return { state, usedTools: false };

  let nextState = state;

  for (const [, toolId, rawInput] of matches) {
    const input = JSON.parse(rawInput);
    const decision = ports.toolPolicy.canUseTool({ agent, toolId });
    if (!decision.allowed) throw new Error(decision.reason);

    const tool = ports.tools[toolId];
    if (!tool) throw new Error(`Missing tool implementation for ${toolId}`);

    ports.renderer?.toolStarted?.({ toolId, input });
    const output = await tool.invoke(input);
    ports.renderer?.toolCompleted?.({ toolId, output });

    nextState = {
      ...nextState,
      toolResults: [
        ...nextState.toolResults,
        { agentId: agent.id, toolId, input, output },
      ],
    };
  }

  return { state: nextState, usedTools: true };
}

The tool marker is just text. The system only becomes trustworthy when parsing, policy, and execution are separate steps.

File: src/core/loadSkill.js
import { readFileSync } from "node:fs";
import { dirname, resolve } from "node:path";
import { fileURLToPath } from "node:url";

const projectRoot = resolve(dirname(fileURLToPath(import.meta.url)), "../..");

function parseFrontmatter(markdown, location) {
  const match = markdown.match(/^---
([\s\S]*?)
---
?([\s\S]*)$/);
  if (!match) throw new Error(`Skill is missing frontmatter: ${location}`);

  const metadata = {};
  for (const line of match[1].split("
")) {
    const separator = line.indexOf(":");
    if (separator === -1) continue;
    const key = line.slice(0, separator).trim();
    const value = line.slice(separator + 1).trim();
    metadata[key] = value.replace(/^"(.*)"$/, "$1");
  }

  return { metadata, body: match[2].trim() };
}

export function loadSkill(name) {
  const location = resolve(projectRoot, ".agents", "skills", name, "SKILL.md");
  const markdown = readFileSync(location, "utf8");
  const { metadata, body } = parseFrontmatter(markdown, location);

  return {
    name: metadata.name,
    description: metadata.description,
    location,
    body,
  };
}

Why this matters: skills let you add reusable behavior as plain data and Markdown. That keeps the core runtime unchanged while the agents still become more specialized.

import ollama from "ollama";

export function createOllamaLlm() {
  return {
    async streamChat({ model, messages, options = {}, onToken }) {
      const stream = await ollama.chat({
        model,
        messages,
        options,
        stream: true,
      });

      let content = "";
      for await (const chunk of stream) {
        const token = chunk.message?.content ?? "";
        if (token) {
          content += token;
          onToken?.(token);
        }
      }

      return { content: content.trim() };
    },
  };
}

export function createConsoleRenderer() {
  return {
    stepStarted({ step }) {
      console.log(`
▶ ${step.id}`);
    },
    stepCompleted() {
      console.log("
");
    },
    agentStarted({ agent, followUp = false }) {
      const label = followUp ? `${agent.name} (after tool)` : agent.name;
      process.stdout.write(`
${label}: `);
    },
    token(token) {
      process.stdout.write(token);
    },
    toolStarted({ toolId, input }) {
      console.log(`
🛠 ${toolId}`, input);
    },
    toolCompleted({ output }) {
      console.log(`
✓ ${output.title}`);
    },
  };
}
File: src/plugins/lightpandaBrowser.js
import { once } from "node:events";
import net from "node:net";
import { lightpanda } from "@lightpanda/browser";
import puppeteer from "puppeteer-core";

function wait(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

function isPortOpen(host, port, timeoutMs = 400) {
  return new Promise((resolve) => {
    const socket = net.createConnection({ host, port });
    const done = (value) => {
      socket.removeAllListeners();
      socket.destroy();
      resolve(value);
    };
    socket.setTimeout(timeoutMs);
    socket.once("connect", () => done(true));
    socket.once("timeout", () => done(false));
    socket.once("error", () => done(false));
  });
}

async function connectWithRetry(browserWSEndpoint, retries = 20, delayMs = 250) {
  let lastError;
  for (let attempt = 0; attempt < retries; attempt += 1) {
    try {
      return await puppeteer.connect({ browserWSEndpoint });
    } catch (error) {
      lastError = error;
      await wait(delayMs);
    }
  }
  throw lastError ?? new Error("Failed to connect to Lightpanda");
}

export async function createLightpandaBrowserSearchTool() {
  const host = "127.0.0.1";
  const port = 9222;
  const browserWSEndpoint = `ws://${host}:${port}`;
  const hadExistingServer = await isPortOpen(host, port);

  const processRef = hadExistingServer
    ? null
    : await lightpanda.serve({ host, port, obeyRobots: true });

  const processExitPromise = processRef
    ? once(processRef, "exit").then(([code, signal]) => ({ code, signal }))
    : null;

  const browser = await connectWithRetry(browserWSEndpoint);

  return {
    id: "browser.search",
    async invoke({ query }) {
      const page = await browser.newPage();
      try {
        await page.goto(`https://wiby.me/?q=${encodeURIComponent(query)}`, {
          waitUntil: "domcontentloaded",
          timeout: 15000,
        });

        const firstResult = await page.$eval("blockquote", (block) => {
          const link = block.querySelector("a");
          return {
            title: link?.textContent?.trim() ?? "Search result",
            url: link?.href ?? "",
            snippet: (block.textContent ?? "").trim(),
          };
        });

        if (!firstResult.url) throw new Error("No search result URL found");

        try {
          await page.goto(firstResult.url, {
            waitUntil: "domcontentloaded",
            timeout: 20000,
          });

          return await page.evaluate(() => ({
            title: document.title,
            url: location.href,
            extract: (document.body?.innerText ?? "").slice(0, 2500),
          }));
        } catch (error) {
          return {
            title: firstResult.title,
            url: firstResult.url,
            extract: firstResult.snippet.slice(0, 2500),
            note: `Failed to open result page: ${error.message}`,
          };
        }
      } finally {
        await page.close().catch(() => {});
      }
    },

    async stop() {
      browser.disconnect();
      if (!processRef || !processExitPromise) return;

      if (processRef.exitCode === null && processRef.signalCode === null) {
        processRef.kill("SIGTERM");
      }

      const exitedGracefully = await Promise.race([
        processExitPromise.then(() => true),
        wait(2000).then(() => false),
      ]);

      if (!exitedGracefully && processRef.exitCode === null && processRef.signalCode === null) {
        processRef.kill("SIGKILL");
        await processExitPromise.catch(() => {});
      }
    },
  };
}

export function createToolPolicy() {
  return {
    canUseTool({ agent, toolId }) {
      if (!agent.allowedTools?.includes(toolId)) {
        return {
          allowed: false,
          reason: `Agent ${agent.id} is not allowed to use ${toolId}.`,
        };
      }
      return { allowed: true };
    },
  };
}

import { personaDebateSystem } from "./systems/personaDebate.js";
import { runSystem } from "./core/runSystem.js";
import { createOllamaLlm } from "./plugins/ollamaLlm.js";
import { createLightpandaBrowserSearchTool } from "./plugins/lightpandaBrowser.js";
import { createConsoleRenderer } from "./plugins/consoleRenderer.js";
import { createToolPolicy } from "./plugins/toolPolicy.js";

const DEFAULT_TOPIC = "Should browser-use agents obey robots.txt by default?";

function parseArgs(args) {
  const input = {
    topic: DEFAULT_TOPIC,
    statement: "",
    searchQuery: "",
    requireSearch: false,
  };

  for (const arg of args) {
    if (arg.startsWith("--topic=")) input.topic = arg.slice("--topic=".length);
    else if (arg.startsWith("--statement=")) input.statement = arg.slice("--statement=".length);
    else if (arg.startsWith("--search=")) input.searchQuery = arg.slice("--search=".length);
    else if (arg === "--require-search") input.requireSearch = true;
  }
  return input;
}

const llm = createOllamaLlm();
const browserSearch = await createLightpandaBrowserSearchTool();

try {
  const finalState = await runSystem({
    system: personaDebateSystem,
    input: parseArgs(process.argv.slice(2)),
    ports: {
      llm,
      renderer: createConsoleRenderer(),
      toolPolicy: createToolPolicy(),
      tools: { "browser.search": browserSearch },
    },
  });

  console.log("\n\nFINAL STATE:");
  console.log(JSON.stringify(finalState, null, 2));
} finally {
  await browserSearch.stop();
}

What software design patterns did we use?

This workshop is small, but the architecture is not random. It borrows several modern software engineering patterns that keep systems understandable as they grow.

Pattern

Functional Core, Imperative Shell

buildMessages, runSystem, and most state transitions stay deterministic. Browser calls, model streaming, and console output stay at the edges.

Pattern

Ports and Adapters

The runtime depends on ports like llm, renderer, toolPolicy, and tools. Concrete plugins adapt Ollama and Lightpanda into that shape.

Pattern

Plugin Architecture

LLM, browser search, rendering, and policy are swappable modules. The runtime does not need to change when one of these implementations changes.

Pattern

Strategy Pattern via Data

The active behavior changes because the system definition changes, not because the runtime branches on class types. Agents, tasks, and allowed tools are all data-driven strategies.

Pattern

Explicit State Passing

State is never hidden inside an object instance. Each step receives state and returns new state. That makes replay, testing, and reasoning much easier.

Pattern

Policy Gate / Guardrail

Tool usage passes through an explicit approval layer. The model can suggest actions, but policy decides what the system may actually execute.

13

Best practices for building agents this way

The workshop code is one implementation. These practices are the more general lesson: they help students build useful agent systems without needing a giant framework first.

Best practices
  • Keep agent identity, tools, and skills as plain configuration before turning them into classes
  • Separate planning from execution so the runtime can stay generic
  • Treat tool requests as untrusted model output until parsed and policy-checked
  • Stream tokens for UX, but store final content as explicit state
  • Prefer narrow, read-only tools first. They are easier to reason about and debug
  • Use skills as reusable instruction modules instead of endlessly growing personas
Agent-building patterns
  • Planner + Executor: a system definition plans steps, runtime executes them
  • Toolformer-style augmentation: the model can ask for tools, but the system orchestrates the call
  • Human-readable capabilities: skills live in Markdown and remain inspectable
  • Retry and fallback: connect retry logic and browser fallback results keep the run alive
  • Deterministic demo mode: --require-search guarantees the browser path when teaching
  • State snapshot mindset: every step leaves a serializable record you can save or replay later

The deep lesson is not “agents need a framework.” It is “agents need clean boundaries, explicit state, and boring runtime rules.”

Closing takeaway

Agentic AI systems are not just prompts. They are workflows over explicit state, with tools guarded by policy and side effects isolated behind plugins.

Keep the core boring. Put opinions in system definitions. Put side effects in plugins. Pass state explicitly.
